## 7. API Contract and Integration Requirements

Inspect the actual frontend API client and backend OpenAPI specification, if available.

For each implemented endpoint, ensure that the contract clearly defines:

- HTTP method and path.
- Authentication requirements.
- Required roles and ownership permissions.
- Request parameters and body.
- Response schema.
- Validation rules.
- HTTP status codes and error responses.
- Pagination and filtering conventions.

Use consistent JSON response and error formats where compatible with the existing application.

Use appropriate HTTP status codes, including:

- `200` for successful retrieval or updates returning a body.
- `201` for successful resource creation.
- `204` for successful operations with no response body.
- `400` for invalid operations where appropriate.
- `401` for missing or invalid authentication.
- `403` for authenticated users lacking permission.
- `404` for unavailable resources.
- `409` for conflicts such as duplicate registrations.
- `422` for request validation failures where appropriate.
- `500` for unexpected server failures without leaking internal details.

Do not force a new response convention onto existing frontend code without checking compatibility.

Ensure the OpenAPI documentation reflects actual behavior. Document any endpoint or contract changes that Vanshika needs to integrate.
